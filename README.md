# ことばポケット / ai-translator

iPhone・Chromebook向けの静的な翻訳ノートです。GitHub Pagesで無料公開でき、有料API・APIキー・外部AIアカウントは不要です。

**今回追加した日英WASM翻訳は、実装済みですが実モデルによる翻訳成功は未検証です。開発環境からHugging Faceへの通信が403で拒否され、モデル取得ができませんでした。iPhone Safari実機も未検証です。「iPhoneで翻訳成功を確認済み」とは扱わないでください。** 模擬APIの統合テスト、実ONNXの基本演算テスト、実OCRテストは翻訳モデルの検証と区別しています。

## iPhoneで日英翻訳を試す手順

このブランチを確認してマージし、Pagesの公開が完了してから行います。

1. 新しいiOSのSafariで公開サイトを開きます。実機検証の出発点はiOS 17以降を想定していますが、動作保証・必要メモリの最低値は未確定です。
2. 以前のタブ・ホーム画面アプリを閉じ、オンラインで開き直します。履歴を残すため**サイトデータは削除しないでください**。
3. 翻訳モデルで「OPUS-MT（日英・WASM）」を選びます。WebGPUは必要ありません。
4. 「設定・言語」で原文を「英語」、翻訳先は日本語になることを確認します。最初は自動判定より手動設定をおすすめします。
5. `Hello, how are you?` を入力し、「翻訳する」を押します。
6. 配布元が公開するモデル情報から、ライセンス・固定リビジョン・必要ファイル候補の容量を取得します。内容を確認してモデル読み込みに同意します。本文は配布元へ送信しません。
7. ダウンロードのファイル別MB表示と、分割文章の翻訳進行を待ちます。初回はWi-Fi推奨です。メモリ負荷を下げるため画面を開いたまま、他の重いアプリを閉じて試してください。待てない場合は「中止」を押せます。
8. 日本語になったことを確認します。反対方向は原文を「日本語」、外国語を「英語」にして `私は猫が好きです。` を入力します。方向ごとに別モデルです。
9. エラーなら表示文を確認します。通信制限、配布元エラー、容量不足、WASM非対応、メモリ不足などがあり得ます。**成功扱いにしたり架空の結果に置き換えたりしません。**

iPhoneではWebKitのメモリ制限でタブが終了する可能性があります。Workerを使い、WASMは1スレッド・q8・1方向ずつメモリに置く設計ですが、実機の速度・ピークメモリは未計測です。まず短い文章で確認してください。

Chromeでは対応APIが利用可能な場合に維持し、言語ペア非対応の場合は日英WASMを案内します。WASM版は現時点で日英のみです。中国語・韓国語・フランス語・スペイン語などはChrome側が対応する場合だけ翻訳できます。

自動判定APIがない環境では日英前提の簡易判定です。かなを含む文を日本語、ラテン文字を英語と仮定します。フランス語などは誤判定するので手動指定してください。漢字のみ・判定不能の文には手動指定を案内します。

## モデル、容量、ライセンス

### 日英翻訳で参照する公開モデル

| 方向 | ONNX配布リポジトリ | 元のモデル |
|---|---|---|
| 英語 → 日本語 | [Xenova/opus-mt-en-jap](https://huggingface.co/Xenova/opus-mt-en-jap) | [Helsinki-NLP/opus-mt-en-jap](https://huggingface.co/Helsinki-NLP/opus-mt-en-jap) |
| 日本語 → 英語 | [Xenova/opus-mt-ja-en](https://huggingface.co/Xenova/opus-mt-ja-en) | [Helsinki-NLP/opus-mt-ja-en](https://huggingface.co/Helsinki-NLP/opus-mt-ja-en) |

**各モデルのダウンロード容量・モデルカードのライセンス・現在の配布状態は、開発環境では取得できず未確認です。推測の容量を掲載していません。** モデルはこのGitリポジトリには含めません。

アプリは公開レジストリから固定コミットSHA、必要なq8 ONNXファイルと各サイズを調べ、モデルカードのライセンスを検査してから確認画面を表示します。必要ファイル候補の合計は、キャッシュ・追加ファイルなどで実際の通信量と異なる場合があります。不明なライセンスや必要な量子化ファイルがない場合は止めます。受け付けるライセンスはApache-2.0/MIT/CC-BY-4.0で、個別モデルの許諾確認は必須です。上流OPUS-MTのソフトウェア自体はMITですが、それだけで全モデルが同じ許諾とは判断しません。

容量以外の条件：WASM SIMDに対応する比較的新しいブラウザ、Module Worker、Cache API、HTTPSが必要です。数百MB〜1GB以上の空きメモリが必要になる可能性がありますが、これは注意の目安であり測定した最低要件ではありません。Safariでの最大メモリ・速度は今後実測します。180文字ごとに保守的に分割し、長文をモデルの入力上限で黙って切り捨てることを避けています。分割で文脈・訳の品質が落ちる場合があります。

バイト単位の正確な容量・SHA-256・配布元・固定バージョンは [vendor-manifest.json](vendor-manifest.json)、配布ライセンスは [licenses](licenses/) に保存しています。`tessdata_fast`は固定コミット `87416418657359cb625c412a48b6e1d6d41c29bd` から取得しました。OCRの他言語は未追加・未検証です。選択したOCR言語は認識を開始したときに同じGitHub Pagesサイトから読み込みます。

- 公式Webサービス：無料枠・利用制限・年齢条件に従います。WebへのログインとAPI契約は別で、無料枠を保証するものではありません。
- API連携：すべて未接続、別契約・料金確認が必要です。自動課金の仕組みはありません。

[OpenAIモデル資料](https://developers.openai.com/api/docs/models)、[Geminiモデル資料](https://ai.google.dev/gemini-api/docs/models)、[Anthropicモデル資料](https://platform.claude.com/docs/en/about-claude/models/overview)、[Qwen公式案内](https://qwen.ai/)で利用者自身も確認できます。公式仕様を確認できるまでモデルIDはnullです。表示名をAPI IDに流用しません。

## 公式Webサービスを使う補助モード

1. テキスト画面に原文を入れ、言語を指定します。
2. 「サービス」で利用するサービスと翻訳指示（自然・直訳・丁寧）を選び、「原文と翻訳指示をコピー」を押します。コピーできなければ表示された指示欄を手動コピーします。
3. 年齢条件・保護者同意・学校の規則を満たす公式サイトだけを別タブで開き、ご自身で貼り付け・翻訳を実行します。登録・契約はこのアプリの利用に必須ではありません。
4. 訳文を「ことばポケット」へ手動で貼り付け、表示されたモデル名を分かる場合だけ自己申告で入力します。
5. 「訳文を取り込む」を押すと手動取り込みとして比較に追加します。コピーした時点の原文と言語に紐づけます。履歴保存がオンの場合だけ履歴にも追加します。

外部AIを自動接続したり、結果を自動取得したりしません。ログイン情報・セッションクッキー・非公式API・スクレイピングは使用しません。正規認証以外の回避処理もありません。「Sign in with ChatGPT」等は正式仕様・対応資格を確認できず**未対応**です。`KotobaModels.authentication`に拡張状態だけ分離しています。

専用翻訳モデルは思考量・翻訳スタイルの指示に非対応なので、テキスト画面の設定は無効化します。手動コピー用のスタイルは文章の指示に含めるだけで、適用を保証しません。外部Webの思考量もこちらから制御しません。

## 画像翻訳の使い方

1. 「画像」でJPEG/PNG/WebPを選択します。HEICはJPEG等に変換してください。最大10 MB・20メガピクセル。処理時は長辺1,600px以下に縮小します。
2. 英語・日本語・日本語＋英語から言語を選び、「文字を読み取る」を押します。認識した文章を確認・編集します。OCR信頼度は正確さの保証ではありません。
3. 「この文章を翻訳する」でテキスト画面へ移動します。日英以外は現在のWASMモデルでは翻訳できません。
4. 実際の訳文が出た場合だけ「翻訳結果を画像へ」を押します。手入力した訳文を重ねることも可能ですが、AIが翻訳したものとは扱いません。
5. 重ねる訳文、X/Y位置、文字サイズ、文字色、白背景の有無を調整し、上の元画像と下の編集後画像を比較します。
6. 「完成画像を保存」でPNGを書き出します。iPhoneの保存操作は実機未検証です。

文字認識の最初のブロック位置を重ね位置の目安に使いますが、段組みや複数吹き出しの自動組版は未対応です。写真に白背景付きの文字を重ねる方式で、自然な背景修復ではありません。GPT-Image/Nano Bananaの正式APIによる編集は別の拡張枠のままで接続・実行しません。

## 履歴、比較、データ保護

- 履歴保存は初期値オフ。保存オンの翻訳・手動取り込みだけ保存します。保存をオフにしても既存履歴は消えません。
- IndexedDB名 `kotoba-pocket`、バージョン1、`history`ストア、既存の主キー・日時インデックスを維持します。追加情報は任意フィールドです。旧記録は「方式不明」と表示します。
- 今回から200件を超えた際の自動削除をやめています。容量不足時は保存失敗を通知し、既存記録は削除しません。
- 履歴から「再利用」で原文を戻し、翻訳ボタンで再実行できます。「比較に追加」は履歴を変更しません。
- 比較は原文・言語ペアが完全一致する結果だけを同じグループにします。自動・手動、日時、モデル、言語を表示。モデル名・スタイルが自己申告なら未検証と明記します。
- JSON/CSVには全履歴を出力します。空の場合は0件の有効なファイルです。CSVは先頭の数式記号や制御文字を無害化し、セルの引用符もエスケープします。
- JSON取り込みは最大5 MB・1,000件。全件検証後、1トランザクションで追加します。IDを持ち込まず、既存履歴を上書きしません。再取り込みは重複します。取り込みファイルはAI実行の証明にならないため手動データとして扱います。
- 設定・お気に入り・モデルメタデータはlocalStorage、履歴はIndexedDB、公開ファイルやモデルはCache APIです。入力文・画像の外部アップロードはありません。モデル取得時の通信先には本文を送信しません。
- 画像・比較セッションは再起動時に保持しません。翻訳結果を残す場合は履歴をオンにしてください。
- 個人情報・パスワード・APIキー・秘密情報は入力しないでください。履歴は暗号化保管庫ではありません。学校の共有端末では保存をオフにしてください。書き出したファイルの共有先にも注意してください。
- サイトデータを削除すると履歴・モデル・設定も消えます。ブラウザは空き容量によりモデルキャッシュを自動削除することがあります。オフライン表示とオフライン翻訳の利用可否は別です。

## ChromebookでPRを作り、確認して公開する手順

今回のブランチは `feat/free-local-translation` です。mainへ直接Pushしません。

1. 作業完了メッセージにあるPRまたはPR作成用URLを開きます。
2. 作成画面の場合は `base: main`、`compare: feat/free-local-translation` を確認し、「Create pull request」を押します。
3. 「Files changed」で変更と、このREADMEの未検証事項を確認します。**日英実モデルとiPhone実機の成功を確認できていない点に注意してください。**
4. 公開して試す準備ができた場合だけ「Conversation」へ戻り、「Merge pull request」→「Confirm merge」を押します。確認前にマージする必要はありません。
5. リポジトリの「Actions」で既存Pages処理の完了を待ちます。Pagesの `main / (root)` 設定はそのままです。
6. 公開サイトをオンラインで開いてから、古いタブとホーム画面アプリをすべて閉じ、再び開きます。v3への更新を待ちます。サイトデータ削除は不要です。

## 開発者向けの実行・検証

サイト配信はビルド不要です。Node.jsやnpmを利用者が契約・導入する必要はありません。追加ライブラリはバージョン固定で同梱し、実行時CDNへプログラムを取りに行きません。翻訳モデルだけはHugging Faceから明示的な確認の後に取得します。

```sh
python3 -m http.server 4173 --bind 127.0.0.1 --directory /workspace
```

別ターミナルで（Node.js、Playwright、Chromium、Python3が必要）：

```sh
cd /workspace/ai-translator
node --check script.js
node --check local-engine.js
node --check local-worker.js
node --check enhancements.js
node --check image-editor.js
node tests/browser.cjs
node tests/workspace.cjs
node tests/features.cjs
node tests/upgrade.cjs
node tests/wasm.cjs
node tests/ocr.cjs
node tests/real-translation.cjs
```

| テスト | 内容 |
|---|---|
| browser | 既存の操作・保存・失敗時処理・PWA（成功系のChrome APIは明示した模擬） |
| workspace | モバイル表示、設定、モデル管理、安全な外部案内 |
| features | 手動取り込み・比較・JSON/CSV・入力保持・モデル取得拒否時の表示 |
| upgrade | 公開v2のコミット `9c963f8` → v3、旧タブ待機中の表示、IndexedDBと設定保持、オフライン |
| wasm | **実ONNX Runtime**でIdentity演算。翻訳テストではない |
| ocr | **実Tesseractと実学習データ**で英語・日本語を認識 |
| real-translation | **実OPUS-MTのみ**の日英翻訳。モデル取得不能時は終了コード2とBLOCKED/NOT RUN、成功扱いにしない |

`TEST_BASE_URL`と`CHROMIUM_PATH`で環境を指定できます。実モデルテストは環境のHTTPSプロキシを使用し、TLS検証を無効化しません。現在は配布元への403で未実行です。Safari/WebKit本体も環境のダウンロード制限で導入できず、iPhone幅の確認はChromiumエミュレーションです。

`vendor-manifest.json`はnpm配布物（npmのintegrity検証あり）と固定Gitコミットから導入した公開アセットのSHA-256を記録しています。`tools/vendor-manifest.py`は再記録用であり、変更されたバイナリを無条件に信頼するためのものではありません。更新時は配布元・ライセンス・integrityを確認してから変更してください。今回はブラウザ版だけを使うため、一時ディレクトリへのnpm導入時にNode向けネイティブインストールスクリプトは実行していません。

画面を変更したら `sw.js` のシェル版とHTML/SHELLの `?v=` を同時に更新してください。現在は `kotoba-pocket-shell-v3`。大きなWASM/OCRデータは必要時に別のruntimeキャッシュへ保存し、文章・画像をService Workerで保存しません。Transformersのモデルキャッシュはシェル更新で削除しません。
